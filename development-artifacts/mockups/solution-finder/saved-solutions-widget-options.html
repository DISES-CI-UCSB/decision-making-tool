Saved Custom Solutions Widget — Layout Exploration

Baseline (today) plus 3 alternative layouts for the "find & restore a saved solution" panel in the Conservation Solution Search modal. Sample names deliberately vary in length ("balooga" vs. a long name) to stress-test each layout.

Baseline (shipped today)

Fixed-width pills, shrink-to-fit, horizontal scroll

Already shipped fix: pills hug their label width (w-fit) instead of a fixed w-48. Row still scrolls horizontally past a handful of items, and shows no solution-name/timestamp metadata.

Saved custom solutions

Select one to restore its finder controls.

  • Permanently occupies a full-width strip above the 3 main step columns, even before it's used.
  • Horizontal scrollbar only becomes visible on hover in most browsers — easy to miss additional saved items.
  • No solution-name or "saved 2 days ago" context; no delete action.
Option A — smallest change

Wrapping chip cloud (same visual language, no more hidden scrollbar)

Swap overflow-x-auto for flex-wrap. Everything is visible at a glance; panel grows taller instead of scrolling sideways. Still no metadata, but a hover delete "×" is easy to bolt on.

Saved custom solutions

  • Everything visible without a scroll gesture — better discoverability than a hidden horizontal scrollbar.
  • At 12 items, panel can grow to 2–3 rows tall, pushing the 3 step columns down further in a modal with limited height.
  • Hover-reveal "×" is a natural place for delete, but still no room for solution-name/timestamp context.
Option B — recommended structural fix

Compact trigger button + popover list (metadata + delete)

Panel is replaced by a small "Saved solutions (6)" button that opens a flyout. Rows are full-width, so name length is no longer a layout problem, and there's finally room for the underlying solution name, relative timestamp, and a delete icon.

  • Reclaims the full-width strip for the 3 step columns until the user actively wants to browse saved solutions.
  • Vertical list + normal scroll handles 12 items more gracefully than a horizontal strip; room for solution-name + timestamp + delete.
  • Costs one extra click before restoring a scenario, and needs outside-click/escape-to-close behavior.
Option C — most minimal footprint

Single searchable combobox (one row, dropdown-on-type)

Collapses search + browse into one input. Typing (or clicking) opens a dropdown of matches with the same metadata as Option B. Smallest permanent footprint of all four options — a single row, always.

  • Smallest permanent footprint (one row) of the four options; familiar "command palette" / autocomplete pattern.
  • Search and browse are the same control, which is efficient but hides the full list until you interact with it (no at-a-glance "you have 6 saved" signal unless a badge/counter is added elsewhere).
  • Delete would need a secondary affordance (e.g. an icon inside each dropdown row, or a "manage saved solutions" link).
