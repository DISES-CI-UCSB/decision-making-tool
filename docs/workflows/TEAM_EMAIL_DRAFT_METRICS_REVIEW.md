# Draft Email: Metrics Review Request

**Subject:** Action Required: Two-Phase Metrics Review for Decision Tool (Area 4.4)

---

Hi team,

Following up on our discussion from this week's meeting, I'd like to formalize our two-phase approach to finalizing the metrics for the decision-making tool. Think of these metrics as the **Lego building blocks** we'll use to construct the app. The arrangement and display of these blocks is flexible and can be decided later, but first we need to agree on which blocks we actually have in our toolkit.

The good news: deciding which metrics to include or exclude is much more straightforward than deciding how to arrange and present them in the UI. Let's focus on that first.

## 📋 What You're Reviewing

**Document:** [Master Design Document - Area 4.4: Metrics Reference Tables](link-to-document)

Area 4.4 contains all 91 metrics currently proposed for the tool, organized into tables:
- **4.4.1** - Solution Overview Panel Metrics (17 metrics)
- **4.4.2** - AOI Dashboard Metrics (47 metrics)
- **4.4.3** - Scenario Comparison Panel Metrics (4 metrics)
- **4.4.4–4.4.8** - Thematic Report Metrics (18 metrics)

## 🎯 Phase 1: Identify What to Include/Exclude
**Deadline: Before Monday's tech team meeting (Date)**

Please review Area 4.4 on your own time and:

1. **Flag any metrics you think we should EXCLUDE**
   - Add a comment directly in the document explaining why
   - Mark with "EXCLUDE" or similar clear language

2. **Suggest any metrics you think we should ADD**
   - Add a comment with your proposed new metric
   - Use notation like "1a" or "2b" after an existing metric index (e.g., "After metric #5, add 5a: [Metric Name]")
   - This helps me track new additions before re-numbering everything
   - Include: Metric name, description, units, and why it's needed

**Note:** Don't worry about calculation formulas or data availability yet—that's Phase 2. For now, just focus on which metrics are scientifically/strategically important.

## 🔬 Phase 2: Document Calculations & Data Sources
**Timeline: Following week after Phase 1 discussion**

Once we've agreed on which metrics to include, we'll work together to:
- Define calculation formulas for any metrics marked "TBD"
- Verify data sources and layer availability
- Update the "Asset Status" column (✅ Available / ❓ Unknown / ❌ Missing)
- Flag any metrics that can't be implemented due to data gaps

We'll tackle this collaboratively during our Monday meetings and async in the document.

## 🎯 Goal: Metrics v1.0 in ~2 Weeks

By the end of this two-phase process, we should have:
- ✅ Agreed-upon list of metrics (no more "Pending" in the Desirability column)
- ✅ Documented calculations and data sources
- ✅ Version 1.0 of the metrics finalized

We can then version the document as "1.0" and iterate from there (1.1, 2.0, etc.) as needed.

## 💡 Why This Approach?

As I mentioned in our conversation with Nick, these metrics are the foundational building blocks. Once we know what blocks we have, we can be flexible about how we arrange them in the UI. But we need to make these core decisions first before we can move forward with implementation.

The more people involved in a decision, the longer it takes—so let's be efficient: handle the straightforward "do we need this metric?" decisions quickly, then tackle the more complex arrangement and presentation questions later.

- **Following Week:** Phase 2 - formalize calculations and data sources
- **Week of (Date):** Finalize Metrics v1.0
